# Phase 2 — API contract

**Status: Phase 2 baseline.** [OpenAPI](openapi.json) is the interface source for the Next.js client and NestJS backend. The contract follows [OpenAPI 3.1](https://spec.openapis.org/oas/v3.1.0.html).

- The proposed base path is `/api/v1` on the application origin. Sign-in sets HTTP-only access and refresh cookies. Each opaque credential carries a session selector and a secret verified against the Redis hash. Browser writes authenticated by cookies require the CSRF header. Next.js reads a separate, script-readable CSRF cookie and echoes its signed, session-bound value in that header. The unlock header carries a separate short-lived credential from the emailed verification link.
- Task dates and slot times use Vietnam local date and 24-hour time. Note timestamps and server instants use offset-aware ISO timestamps. The backend computes the displayed status. A timetable response covers seven dates, with date filters intersecting that week. Table and list views use one-based pages. Use a deterministic sort with an ID tie-breaker. Additional sort and filter fields remain open.
- An edit to a recurring task uses its anchor occurrence. Selecting other weeks adds occurrences to the edit. A moved date past the series month is set to that month's last day in Vietnam time, and the deadline follows the adjusted date. The delete request carries the displayed week for the preserve-week option. Validate ownership and series membership before applying changes. Updating progress targets one task. See [scheduling](data-and-scheduling.md).
- Support uploads use three steps. Ask NestJS for a signed upload intent, send the image directly to Cloudinary as multipart form data, then send request text and the intent ID to NestJS as JSON. NestJS verifies the uploaded asset against Cloudinary and stores its URL in PostgreSQL. The viewing endpoint returns a temporary URL and expiry after checking access. This draft proposes interpreting 10 MB as 10,000,000 bytes. See [authentication and support](auth-and-support.md).
- Errors carry a stable code, message and request ID. A missing resource and a resource outside the caller's ownership return the same 404. An authenticated caller without ADMIN role receives 403 on an ADMIN operation.
- A conflicting series operation returns 409 and leaves the batch unapplied. Reload the week before retrying. If a create or support action times out, check for an existing item before resubmitting. Idempotency policy for those operations remains open.
- Expired activation proof returns 410 and the UI offers resend. Oversized evidence returns 413. Unsupported image format returns 415. Temporary dependency failure returns 503. Rate limits return 429.

## Decisions and gates carried forward

- At IM-01, confirm Node and dependency versions against the official platform documentation. At IM-02, choose a migration tool and verify the selected PostgreSQL and Redis clients in disposable environments. Existing Docker access limitations apply until retested.
- Before IM-07, specify retry and cleanup schedules, support evidence retention and whether to allow any additional image formats beyond PNG, JPG/JPEG and WebP. Preserve the confirmed 10 MB cap. Specify any additional per-screen filters before implementing their list views.
- On staging before release, validate Vercel rewrite and cookies, Neon quotas and restore, Redis rotation, Gmail delivery and retry, and Cloudinary upload and private delivery at the agreed limit. An unavailable provider or approval is recorded as blocked or not run.
- For each approved task, use the plan and scope gate, capture actual test output, review the changes and update state. Run `python harness/checks/check.py context`, the task scope check and `git diff --check` as appropriate. Mark a task complete only when its acceptance and applicable quality gates have evidence.

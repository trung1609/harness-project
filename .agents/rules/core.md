# Repository agent rules

Follow AGENTS.md and higher-priority instructions. Read only task-relevant project documents. Separate VERIFIED, ASSUMPTION, PROPOSAL, and BLOCKED; do not turn planned features or technology into approved requirements. Never infer business rules, architecture decisions, API contracts, versions, or test outcomes.

Stay in the explicitly approved phase and task scope; do not advance phases without the user's confirmation. Inspect git status and preserve existing changes. Do not destroy data, weaken tests, disclose secrets, bypass a gate, or change architecture without authorization. Respect user instructions when a generic skill conflicts with this project workflow.

Use PLAN → IMPLEMENT → VERIFY → EVALUATE. Inspect actual failures, diagnose the cause, and make no more than three self-fixes for the same issue; then mark BLOCKED with evidence. Report actual PASS, FAIL, NOT RUN, NOT APPLICABLE, or BLOCKED. Markdown instructions are not enforcement.

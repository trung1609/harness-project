# Phase gates

Phase 0 builds and verifies the Harness, without business implementation. Phase 1 elicits and confirms requirements. Phase 2 designs architecture and specifications. Phase 3 breaks approved designs into scoped tasks. Phase 4 implements approved tasks one at a time. Phase 5 verifies the system. Phase 6 covers deployment and handoff. Phase 7 improves the Harness using observed failures.

Each phase requires explicit user confirmation before starting. The user may authorize a focused task within the current phase. A completed task or passing CI does not itself approve a phase transition. Record decisions and open issues in repository state; do not invent phase deliverables.

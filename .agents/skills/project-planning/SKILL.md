# Implementation planning

Read the approved source and docs/plans/task-template.md. Create tasks with ID, objective, dependencies, approved scope, expected changes, acceptance criteria, meaningful test cases, verification commands and definition of done. Identify the baseline, pre-existing changes, applicable gates, unresolved questions and task order. Trace acceptance criteria to the approved source and distinguish proposed work from approved work.

Do not imply task or phase approval from a plan. Keep tasks independently reviewable and implement one approved task at a time unless the user requests otherwise.

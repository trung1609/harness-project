# Project review

Inspect the approved task, relevant spec and actual diff; distinguish findings from assumptions and unverified concerns. Prioritize defects, security issues, regressions, out-of-scope edits, missing tests, unverified gates and specification mismatches. Cite file locations and explain concrete impact. Do not print secrets. Avoid claiming an independent review if the author performs it. Report tests actually run and residual risks; do not make speculative feature requirements.

# Harness improvement

Start from a real failure or explicit request. Inspect the evidence and relevant guardrails, distinguish root cause from symptom, and choose the smallest change addressing it. Prefer an executable check with meaningful success and failure tests where the rule is machine-verifiable; explain what remains dependent on review. Avoid duplicate skills and policies. Verify the change, record results and limitations, and update project state when appropriate. Do not introduce business requirements or advance phases.
